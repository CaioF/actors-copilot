# Personal DNA, vault and acting coach

## Personal DNA chat

**Entry and layout.** Sidebar Personal DNA opens `/chat`, a standalone layout with Back to Dashboard, chapter navigation and conversation. A production Economy session showed “Continue your discovery”, “Personal DNA Extraction”, four chapter controls (Foundation & Persona, World & Relational Power, Inner Shadow & Vulnerability, Core Fuel & Creative Drive), How DNA Extraction Works and Upload Baseline. This was a page load, not a completed conversation.

`/personal-dna` is a separate placeholder page in the mapped source: its “Start Building DNA” button has no handler there. The sidebar points directly to `/chat`; verify current behavior before treating the placeholder as a working navigation path.

**Drive.** Choose a chapter in the sidebar; inspect the active chapter and its progress. Enter a synthetic message in the textarea (`Ask me anything...` in the observed state); the main button changes its accessible name from `Start recording` to `Send message`. Submit, wait for assistant content and enabled input, then navigate away and reopen. Confirm the specific user message and response persist in the intended session; test errors and retry separately. Shortcuts include Change the subject, I don't understand the question and End Session; they can send messages or mutate session state, so exercise on a disposable identity. The help modal and DNA Reservoirs control should open/close without sending. Attach file and baseline uploads send content to processing services; use synthetic documents only. Recording requires permission and transcription services; test denial, stop and failure independently.

**Observed chat controls, 2026-11-17.** In production, Chrome 157 headless at 1440×900 with the seeded Economy test session: `How DNA Extraction Works` opened its help modal and `Close help modal` dismissed it. Reopening help → `Upload Baseline` opened the baseline form; `Cancel` returned to chat. `DNA Reservoirs` opened and closed its popover. No POST to `/api/dna/` was observed during these control interactions after chat loaded. The check did not select a chapter, send a message, update the vault, submit a baseline or audit Firestore writes. Source: `app/chat/page.tsx`, `components/chat-help-modal.tsx`, `components/chat-input.tsx`.

**State and boundaries.** `hooks/use-chat.ts` subscribes to `users/{userPath}/dnaSessions/{sessionId}` and messages, and stores tracker state in localStorage; a fresh browser context and a reload test different persistence boundaries. DNA endpoints include `/api/dna/chat`, `/baseline`, `/synthesize`, and transcription. AI response, extraction, vault entry and synthesized profile are distinct outcomes; do not infer one from another. Check `components/chat-input.test.tsx`, `components/chat-messages.test.tsx`, `lib/dna/extraction/` tests and source when relevant.

**Baseline interaction and persistence (source-derived).** Dashboard → Upload Baseline opens `HistoryUploadModal`; the shared upload control accepts PDF or DOCX or pasted text, and Save Baseline enables when either is present. Cancel unmounts the draft. Submitting sends an authenticated multipart POST to `/api/dna/baseline`; when both file and text are present the route uses the file. The route trims extracted content and rejects fewer than 50 characters before calling the model. On success it merges `baselineHistory` and extracted profile fields into `users/{userPath}/profile/master`; it is a real AI call and database write, not just a file selection. The route also lists plain text as an accepted file type, whereas the shared picker exposes PDF/DOCX; do not assume API acceptance makes TXT selectable in the UI. See `components/history-upload-modal.tsx`, `components/auditions/step/step-upload.tsx`, `app/api/dna/baseline/route.ts`.

**Observed, 2026-11-17.** In production, Chrome 157 headless at 1440×900 with the seeded Economy test session: an empty baseline had Save disabled; synthetic text enabled it, and Cancel followed by reopening restored an empty form. Selecting the tracked synthetic DOCX enabled Save; removing it disabled Save again. A request listener observed no POST to the baseline endpoint during this cancellation check. No submission, extraction, server-side file parsing or persistence was tested.

**Confirmed error-message defect, 2026-11-17.** In that same production environment, submitting the 21-character synthetic text `Synthetic short text.` with no file yielded HTTP 400 and the API reason “Content too short for AI analysis.” The form retained the draft, but the displayed toast said it could not read the file and suggested a damaged, scanned or password-protected PDF; it did not explain the length requirement. The inspector's opt-in short-baseline check expects an actionable length message and currently fails against production. The source places the length rejection before the AI invocation or Firestore write; the browser observation establishes the rejection and visible message, not an independent database audit. No fix is included in this map PR.

**Observed, 2026-11-17.** Production, Chrome 157 headless, 1440×900, Economy test account and seeded real session: typing a synthetic message produced an HTTP 200 and an assistant response; after the processing control became enabled, both messages were visible after reload. An earlier run reloaded before processing finished and failed the reload check; that was insufficient evidence of a product defect. Synthetic messages remain in the test account. Keyboard typing mattered: Puppeteer's `fill` left visible text without changing the controlled Send action in this run. This did not establish an extraction or a vault update.

## DNA Vault

Open `/dna-vault`. Production Economy showed “Personal DNA Vault”, Refresh, Export and Extract More DNA; data-dependent tabs may appear after loading. Source provides Overview, Insights and Memory tabs; populated Insights has section filters and `Filter deductions...`, Memory has section filters and `Search actor quotes...`, both with Clear search. Test empty/error/populated states and confirm filtering is reversible; Refresh fetches data and Export calls print, not a persistent database export. The empty state links to `/chat`. Verify a new extraction independently of the chat response. Source: `app/(interior)/dna-vault/page.tsx`, `components/dna-vault/`.

Observed 2026-11-17 in production, Chrome 157 headless at 1440×900, using the seeded Economy test session: the populated vault opened all three tabs. Insights and Memory each contained entries; a synthetic nonmatching search showed the corresponding no-match state, and Clear search emptied each input. In both tabs, selecting the first available section showed entries labeled with that section, and All Sections restored the original count. Neither selection reduced the count for this account, so exclusion of entries from other sections remains unverified. This did not verify entry correctness, Refresh, Export or a new extraction.

In a separate seeded Free account on production, the vault finished loading with `No DNA Extracted Yet`. Clicking `Start First Extraction Session` followed its `/chat` link and arrived at `/upgrade`. This is an empty-state observation for one account, not proof of the behavior of a populated Free vault.
