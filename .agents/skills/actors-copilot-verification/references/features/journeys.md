# Cross-feature journeys

Run the relevant journey only when a verified isolated environment and disposable test identity exist. Capture checkpoints, not just the last screen.

1. **Access to work:** sign in → callback/session → dashboard → navigate to a matched protected route → reload → logout → protected route redirects. For free, economy and business, check actual tier/status and the specific proxy matcher before comparing gates. Never fabricate Stripe entitlements in Firestore.
2. **DNA to coach:** send synthetic DNA input → revisit session and vault → open coach → send prompt → reopen coach session. Record whether synthesis/extraction was actually produced; do not infer it from chat text.
3. **Audition to rehearsal:** create a synthetic brief or scene study → save → reload list and detail → enrich with the other type → confirm both results persist → open Reader Copilot → rehearse → return. Check retry and duplicate handling when those paths changed.
4. **Profile publication:** edit synthetic profile → save/reload → publish → open public slug in a clean context → unpublish and verify public behavior. Only in isolated test infrastructure; record exposure and cleanup.
5. **Billing recovery:** isolated Stripe test customer and signed webhook → recovery checkout → complete test flow → verify subscription and webhook-owned billing state → refresh session → check access. Include cancellation/failure as relevant. Hosted checkout, async webhook and client session are separate checkpoints.

If any checkpoint is unavailable, report the exact blocker and nearest check performed; a mocked route test is not an end-to-end pass. See [verification](../verification.md).
